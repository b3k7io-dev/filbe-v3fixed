# Filebe

Android-файловый менеджер для разработчиков: Kotlin + Jetpack Compose + Material 3.

## Сборка

Нужны **JDK 17**, Android SDK Platform 35 и Build Tools 35.0.0. `minSdk = 26` (Android 8.0). Версии зависимостей закреплены: AGP 8.7.3, Kotlin 2.0.21, Gradle 8.9, Compose BOM 2024.12.01. Это выбранный совместимый набор, а не заявление о последних версиях.

1. Распакуйте архив и откройте каталог `Filebe` в Android Studio.
2. Дождитесь Gradle Sync. Android Studio создаст локальный `local.properties` с расположением SDK.
3. Выберите устройство и запустите конфигурацию `app`.

CLI из каталога проекта:

```sh
chmod +x gradlew
./gradlew testDebugUnitTest lintDebug assembleDebug
```

Windows:

```bat
gradlew.bat testDebugUnitTest lintDebug assembleDebug
```

При CLI-сборке укажите `ANDROID_HOME` или `sdk.dir` в собственном `local.properties`. APK: `app/build/outputs/apk/debug/app-debug.apk`. Это debug-подпись; не используйте её для публикации релиза.

Gradle Wrapper (`gradlew`, `gradlew.bat`, `gradle-wrapper.jar`) взят из официального репозитория Gradle, тег `v8.9.0`. SHA-256 wrapper JAR: `498495120a03b9a6ab5d155f5de3c8f0d986a449153702fb80fc80e134484f17`. Проверка контрольной суммы Gradle-дистрибутива задана в `gradle-wrapper.properties`.

## GitHub Actions

В репозиторий нужно загрузить **содержимое** каталога `Filebe`, чтобы `.github/workflows/build.yml` находился в корне репозитория. Workflow запускается на push, pull request и вручную: устанавливает JDK/SDK, выполняет JUnit, Android Lint и сборку Debug, затем загружает `Filebe-debug` в Artifacts конкретного запуска. Секреты/API-ключи для сборки не нужны. Проект не создаёт GitHub Release и не публикует APK в магазин.

## Что реализовано

- Три нижние вкладки: **Файлы**, **Открытый**, **ИИ**.
- Dark / Day / System, полупрозрачные панели, тонкие границы, мятный и металлически-лиловый акценты. Compose `BlurEffect` размывает фоновый слой на Android 12+; на Android 8–11 остаются прозрачность/градиенты без аппаратного blur. Это стеклянная стилизация, не оптическая симуляция преломления и не универсальный backdrop-filter произвольных Android-окон.
- Навигация по обычным путям, внутренней папке приложения, сохранённым SAF-деревьям и опциональному `su`-root.
- Создание папок/файлов, копирование, перемещение, переименование, подтверждаемое безвозвратное удаление, поиск по имени, рекурсивный поиск, ZIP-архивация, свойства.
- Конфликты имён отменяют операцию — молчаливой перезаписи при копировании нет. Для перемещения сначала завершается копирование и только потом удаляется источник. Если источник не удалось удалить, сообщение об ошибке остаётся; копия в назначении может уже существовать.
- Копирование выполняется во временный объект с последующим переименованием. Символические ссылки не обходятся при рекурсивном копировании/ZIP. Предотвращается копирование дерева внутрь себя. Папки между SAF и обычными/root-путями намеренно не копируются: разные пространства имён могут указывать на одну и ту же папку; отдельные файлы можно переносить между ними.
- Текстовый редактор UTF-8 до 1 МиБ, номера строк, эвристическая подсветка, debounce-проверка скобок/длинных строк/хвостовых пробелов. **Это не Kotlin-компилятор, LSP, антивирус или проверка безопасности.** Более сложный синтаксис (например, JS regex literals) может давать ложные диагностики. Для файлов длиннее 100000 символов подсветка отключается. Бинарные и не-UTF-8 файлы редактор отклоняет, не перекодируя их.
- SHA-256-проверка внешних изменений перед сохранением; обычный файл заменяется через временный файл в той же папке. SAF не имеет универсальной атомарной записи, поэтому **перед** записью сохраняются исходные и новые байты в приватной папке Filebe/recovery. Она доступна через плитку «Восстановление SAF». `.original` — исходные байты, `.edited` — новые, `.path` — исходный URI. Для восстановления скопируйте нужную копию в папку назначения и переименуйте. Некоторые провайдеры не поддерживают необходимые операции и вернут ошибку.
- Отдельные WebView для локального ИИ-интерфейса и внешнего браузера.
- Реальный HTTPS Chat Completions API, не имитация ответов. ИИ может предложить полный новый текст; он доступен для просмотра и попадает в редактор только после подтверждения. Изменившийся после запроса файл защищён проверкой пути и ревизии. Автосохранения от имени ИИ нет.

## Доступ к памяти и root

**SAF не предоставляет root-доступ. MANAGE_EXTERNAL_STORAGE тоже не является root.**

- Android 11+: специальный доступ запрашивается через системный экран `ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION`; результат проверяется через `Environment.isExternalStorageManager()` при возврате/возобновлении Activity. Это не обычный runtime permission dialog.
- Android 8–10: обычные READ/WRITE_EXTERNAL_STORAGE runtime permissions, ограниченные `maxSdkVersion=29` в Manifest.
- SAF работает независимо от разрешения всех файлов; сохраняются только действительно выданные системой флаги. Read-only провайдер остаётся read-only. Доступ может быть отозван пользователем/провайдером.
- Android может запрещать выбор корня хранилища, Downloads и Android/data/obb в SAF. Приватные каталоги других приложений и системные разделы недоступны обычному процессу.
- Плитка «Корень / без root» показывает только пути, разрешённые Linux/SELinux и Android.
- Плитка «Root / через su» после предупреждения вызывает установленный **на уже рутированном устройстве** `su`, проверяет UID 0 и использует отдельный backend. Filebe не выполняет рутирование и не обходит запрос менеджера root. На обычном телефоне будет понятная ошибка. SELinux, read-only разделы и ограничения конкретной реализации `su` могут запрещать операции даже UID 0.
- Root-режим показывает виртуальные /proc, /sys и /dev в списках, но чтение содержимого и изменение внутри этих деревьев намеренно запрещены: спецфайлы могут блокироваться и иметь побочные эффекты. Для чтения через su разрешены только обычные файлы.
- Root-команды формируются только из фиксированных шаблонов; пути shell-экранируются, имена проверяются. ИИ/WebView не получают интерфейс произвольного shell. Root-режим опасен: работайте с копиями и не удаляйте системные папки.
- MANAGE_EXTERNAL_STORAGE относится к ограничиваемым разрешениям Google Play. Перед распространением в магазине требуется отдельно проверить действующую политику и обосновать основную функцию файлового менеджера. Эта конфигурация рассчитана на debug/sideload и не обещает одобрение магазина.

## Настройка ИИ

1. Откройте «ИИ» → шестерёнку.
2. Введите полный HTTPS endpoint Chat Completions, API-ключ и доступное вашему аккаунту имя модели. Значения по умолчанию — OpenAI-совместимый пример; наличие доступа к модели/биллинга не гарантируется.
3. Ключ и настройки API хранятся только в ViewModel в памяти: при завершении процесса их нужно ввести снова. Они не записываются в SharedPreferences, web storage или исходники и не передаются JavaScript.
4. Напишите запрос. Чтобы анализировать текущий файл, включите «Приложить текст и путь…» и подтвердите отправку в нативном диалоге, где показан адрес провайдера. Будет отправлен текущий буфер, включая несохранённые изменения.
5. Если модель предложила правку, нажмите «Просмотреть…» и подтвердите применение в редакторе. Затем отдельно сохраните файл.

Ответ модели должен быть JSON с `message` и `replacement` (полный новый файл либо null). Клиент задаёт это системным сообщением; если провайдер/модель не соблюдают формат, отображается ошибка, а не фиктивный результат. Каждый запрос самостоятельный; видимая история не включается автоматически. Лимит запроса 16000 символов, передаваемого файла 64000 символов, ответа API 2 МиБ. Есть HTTP/connect/read timeout; редиректы API не выполняются, чтобы не отправлять ключ на другой endpoint.

**Не отправляйте секреты.** Любой настроенный вами провайдер получает переданный текст и путь. Ключ не защищён от скомпрометированной ОС/root/отладчика, а сохранённые recovery-копии содержат ваш текст. Очистку recovery выполняйте через файловую вкладку с подтверждением удаления.

## WebView-безопасность

- Локальная страница встроена в `AssistantPage.kt` и отдаётся `WebViewAssetLoader` на `https://appassets.androidplatform.net/ui/assistant`. JS/CSS находятся в assets.
- Используется **origin-scoped `WebViewCompat.addWebMessageListener`**, а не глобальный `addJavascriptInterface`. При отсутствии API требуется обновить Android System WebView; небезопасного fallback нет.
- Локальная страница не загружает внешние ресурсы; CSP запрещает inline-скрипты, сетевые запросы, формы и iframe. Ответы выводятся через text nodes, не через `innerHTML`.
- Файловый/content URL доступ, mixed content, popup-окна отключены. Нет выдачи camera/mic/geolocation/file picker permissions.
- Внешний HTTPS-браузер создаётся отдельно **без моста**, не имеет доступа к открытому файлу/API-ключу. Сайты могут работать не полностью из-за отключённых popup, сторонних cookie и недоступного chooser. История браузера/чата при уничтожении WebView не сохраняется; кнопка Android «Назад» переключает вкладки/папки, а не web history.

## Архитектура

```
app/src/main/java/dev/filebe/
  MainActivity.kt       Activity, разрешения, 3 вкладки
  Models.kt             Ref/Entry/OpenDocument/UiState
  FilebeViewModel.kt     StateFlow, операции на IO, редактор, AI workflow
  StorageRepository.kt  единые операции File + SAF + RootAccess
  RootAccess.kt         opt-in su backend
  Theme.kt              Material 3, стеклянные панели, фон
  FilesScreen.kt        список, поиск, контекстные действия, диалоги
  EditorScreen.kt       текст, подсветка, диагностики, запись
  CodeTools.kt          локальный lexer и эвристические проверки
  AiClient.kt           HTTPS Chat Completions, проверка ответа
  AiScreen.kt           изолированные WebView, API settings, preview
  AssistantPage.kt      доверенная локальная страница
app/src/main/assets/    assistant.js, assistant.css
app/src/test/           CodeToolsTest: 7 JUnit-тестов
```

Вкладки реализованы enum/state-навигацией Compose, а не NavController: стек папок находится в ViewModel, открытый документ общий для всех экранов. Долгие операции выполняются на Dispatchers.IO; лексический анализ диагностики — Dispatchers.Default.

## Границы и проверка

Проверено отдельно в JVM: Kotlin 2.0.21 компилирует CodeTools, Models, RootAccess и StorageRepository (с макетами Android API); все **7 JUnit-тестов CodeTools** прошли. Дополнительно прошли **26 проверок файловых операций** на временных обычных файлах и root-бэкенде с подменённой командой su: чтение/запись, shell-экранирование, сохранение, ссылки, копирование, перемещение, ZIP, конфликт имён и SHA-256-конфликт. Это не проверка SAF/Compose, не реальная Android-сборка и не тест на рутированном телефоне.

Это исходный проект, **не заявление о протестированном релизе**. Полная Android-сборка/Android Lint, тесты UI/SAF на устройстве и интеграция с реальным root/API должны быть выполнены в вашей среде/CI. Наличие workflow не означает, что workflow уже запускался.

Нет корзины, распаковки ZIP, многофайлового выделения, LSP, компиляции кода, двоичного редактора, предпросмотра медиа, release-signing, автосохранения черновиков на случай завершения процесса. Поворот экрана сохраняет буфер через ViewModel, но принудительное завершение процесса может потерять несохранённый текст. При работе с системными файлами не сохраняются все расширенные атрибуты/ACL/SELinux-контексты; root-save переносит Unix mode/UID/GID. Файловые операции не являются транзакциями со snapshot-изоляцией от других приложений.

Ручной smoke-test:

1. Android 8–10: отклонить и выдать runtime permissions; Android 11+: отклонить и выдать специальный доступ, отозвать его в настройках.
2. SAF: подключить папку, перезапустить приложение, проверить read-only/отозванный grant и провайдер без isChildDocument.
3. Создать/переименовать/копировать/переместить файл и папку; проверить конфликт имён, отмену удаления, попытку копирования внутрь себя, нехватку места.
4. Создать ZIP с вложенными папками, пробелами и кириллицей; проверить его стандартным архиватором.
5. Открыть UTF-8 с BOM/CRLF, изменить/сохранить; проверить SHA-конфликт при внешнем редактировании и recovery для SAF. Открыть бинарный и файл больше 1 МиБ — ожидается отказ без изменения данных.
6. Проверить обе темы, системное переключение, поворот, экранную клавиатуру, маленький экран и масштаб шрифта.
7. ИИ: пустой/невалидный ключ, HTTP-ошибка, offline, отказ от отправки файла, запрос с файлом, отказ от правки, применение правки, изменение ревизии до применения. Сетевые запросы потребляют реальный API-бюджет.
8. Внешняя страница не должна видеть FilebeBridge; file://, content://, http:// и переход на appassets в браузере должны блокироваться.
9. Root: отсутствие su, отказ менеджера, успешный UID 0 на тестовом рутированном устройстве; сначала работать только с временной папкой. Проверить read-only/SELinux отказ, большие файлы, символические ссылки и сохранение mode/UID/GID.


## Визуальная тема и иконка

Интерфейс использует спокойную чёрно-белую палитру и лёгкие стеклянные поверхности. Редактор оформлен в тёмной палитре VS Code с цветной подсветкой синтаксиса. Вкладка «ИИ» открывает Google AI Mode в браузере; адресная панель и действия браузера собраны в компактную строку. Иконка приложения — предоставленное изображение в `app/src/main/res/drawable-nodpi/filebe_launcher.png`.
